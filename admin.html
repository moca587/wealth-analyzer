🔬 How the Agent Selects Funds — Full Decision Logic
Every fund selection is fully traceable. The engine follows a deterministic 5-stage pipeline with explicit scoring, constraints, and rationale. Below is the complete decision logic — same logic used by both the Research Engine and the Claude API agent.
STAGE 1 — Signal Extraction from Research
For each cached research item (typically 100+ per provider, 1,600+ total), the engine parses the title + summary against keyword lexicons:
  • Sentiment lexicons: 18 bullish phrases (overweight, bullish, favor, top pick, overperform, attractive, compelling, upside, tailwind, constructive, accumulate…) weighted +1 to +4. 16 bearish phrases (underweight, bearish, avoid, cautious, stretched, headwind, exit, trim…) weighted −1 to −4.
  • Asset class detection: 6 classes scanned for phrases (equity, fixed income, real estate, commodity, cash, alternative). Item sentiment is applied to the class as a signed vote.
  • Sector detection: 11 sectors with specific ticker tags (Tech: NVDA/MSFT/QQQ/XLK; Healthcare: LLY/NOVO/XLV; Financials: JPM/XLF; Energy: XOM/CVX/XLE; etc.).
  • Region detection: 7 regions (US, Europe, Japan, China, India, EM, Developed Intl).
  • Theme detection: 11 themes (AI, decarbonization, GLP-1, defense, reshoring, cybersecurity, demographics, water, crypto, dividend growth, quality factor).
  • Ticker extraction: regex against 38-fund universe + 30 common stocks. Each mention recorded with the provider name for conviction scoring.
STAGE 2 — Cross-Provider Consensus Aggregation
Net votes summed across all 16 providers. For each signal (e.g. "overweight Equity"), the engine tracks:
  • Total net votes: sum of all signed sentiments across all items mentioning this signal
  • Provider count: number of unique institutions endorsing the position
  • Top 8 supporting research items: kept for citation in the position's rationale
  • Ticker conviction: tickers mentioned by 3+ providers get a +1 score bonus per additional provider
Example: If BofA, JPM, Morgan Stanley, Goldman, BlackRock, and Pictet all express "overweight equities" with weight 3 each → Equity gets +18 net votes from 6 providers
STAGE 3 — Strategic Asset Allocation (Risk Baseline + Research Tilt)
Starts with a risk-profile baseline, then tilts based on research consensus:
Risk ProfileEquityFixed IncReal EstateCommodityCashAlts
Very Conservative20%60%5%5%10%0%
Conservative30%55%5%3%5%2%
Mod. Conservative40%45%5%3%3%4%
Moderate55%30%7%3%0%5%
Mod. Aggressive65%20%7%3%0%5%
Aggressive75%10%8%2%0%5%
Very Aggressive85%5%5%0%0%5%
Research tilt: each asset class can be shifted ±8 percentage points from baseline based on net votes. Formula:
tilt = max(-8, min(+8, netVotes / 4))
allocation[class] = baseline[class] + tilt
So a class with +24 net votes gets +6% above baseline; a class with −16 net votes gets −4%. Final allocation normalized to sum exactly 100%.
STAGE 4 — Fund Selection from Universe
For each asset class with allocation ≥ 2%, the engine picks specific funds:
  1. Filter candidates by class: only funds where fund.cls === targetClass
  2. Apply hard constraints:
    • If ESG = strict → keep only funds with esg: true flag
    • If liquidity = high → exclude mutual funds and alternatives; ETFs + cash only
    • If tax sensitivity = high → sort ETFs before mutual funds
  3. Score each candidate:
    score = (1 − expense_ratio) ← low cost preferred
         + 2 + (mentions × 0.3) if fund's ticker explicitly cited in research
         − 0.2 if sponsor already used for another position
  4. Sort by score and pick top N funds where:
    • N = 1 if class weight < 12%
    • N = 2 if class weight between 12% and 25%
    • N = 3 if class weight ≥ 25%
  5. Apply max-position cap: if user set maxPosition = 20%, no single position exceeds 20%
  6. Renormalize: all weights scaled to sum to exactly 100%
STAGE 5 — Rationale Generation (per position)
Every fund pick gets a multi-part rationale:
  • Consensus citation: "N/16 providers overweight [class] (+X net votes)"
  • Specific ticker mentions: if applicable, "VTI explicitly mentioned by BlackRock, Vanguard + 2 more"
  • Cost rationale: "Low expense ratio (0.03%)"
  • Constraint match: "ETF wrapper preferred for high tax sensitivity" or "ESG-flagged matches preference"
  • Top 3 research citations: bulleted list of the actual research items that drove the asset-class consensus, each tagged with the providing institution
📝 WORKED EXAMPLE — Moderate Profile, Sample Walkthrough
Brief: risk = moderate · NW = $500k · ESG = none · tax = medium · liquidity = medium · max pos = 20%
Research scanned: 1,420 items across 16 providers

Signals extracted:
• Equity: +28 net votes from 14 providers (overweight consensus)
• Fixed Income: +8 net votes from 11 providers
• Real Estate: −2 net votes (mixed views)
• Cash: −12 net votes (underweight)
• Top theme: AI (16/16 providers, 67 votes)
• Ticker mentions: VTI 4x, IVV 6x, AGG 5x, QQQ 8x

Allocation (Moderate baseline tilted by research):
• Equity: 55% baseline + 7% tilt (28/4) = 62%
• Fixed Income: 30% + 2% = 32%
• Real Estate: 7% − 0.5% = 6.5% (but rounds down, stays at 7%)
• Cash: 0% − 3% (floor at 0) = 0%
• Normalized to 100%

Fund picks for Equity (62% → 3 funds):
• IVV 20% — score = 0.97 + 2 + 1.8 (mentions) − 0 = 4.77 → highest
• QQQ 20% — score = 0.80 + 2 + 2.4 (8 mentions) − 0.2 (BlackRock used) = 5.00 → highest
• VXUS 22% — score = 0.93 + 0 − 0.2 = 0.73 (no mention, but good for diversification)

Rationale for IVV:
14/16 providers overweight Equity (+28 net votes) ·
IVV explicitly mentioned by BlackRock, BofA, JPM + 3 more ·
Low expense ratio (0.03%)
Citations:
• [BofA] "Equities: Overweight quality large caps; mid-single-digit S&P returns"
• [BlackRock] "iShares Top Picks: IVV, AGG, IEMG"
• [JPM] "Guide to the Markets: 60/40 6-8% expected next decade"
🔒 Determinism guarantee: the Research Engine is fully deterministic. Same brief + same cached research → always same output. Run it twice in a row and verify identical fund picks via the Engine Stress Test tab → "Robustness Checks" → "Determinism" test. The only thing that changes the output is (a) you change the brief, (b) new research arrives in the cache, or (c) you modify the fund universe / risk-baseline / scoring constants directly in the code.
🤖 How the Claude API agent differs: the Claude version receives the same client brief + research items + fund universe as the deterministic engine, but uses an LLM to reason narratively over the inputs. It may suggest weights that deviate from the deterministic baseline (e.g. tactical overweights based on theme strength), and can produce richer prose rationale. Both produce the same JSON shape and feed the same Export-to-Proposal button. Pick deterministic for auditability, Claude for narrative reasoning.

Both admin.html and wealth-analyzer.html are static files sharing the same browser origin and therefore the same localStorage. The admin reads + writes specific keys that the main app reads on load:

localStorage keyDirectionDescription
wa_app_versionsharedCurrent app version stamp
wa_pending_profileadmin → mainProfile injected by Profile Manager
wa_pending_proposaladmin → mainRecommendation exported by AI Agent
wa_claude_keysharedAnthropic API key
fhKey, avKey, wa_polygon_key, etc.sharedMarket data provider API keys
wa_research_configadmin onlyProvider feed URLs, enabled state, cached items
wa_admin_constantsadmin onlyEdited RISK_PROFILES, REGIONS, LOAN_DEFAULTS
wa_admin_logsadmin onlyAction audit log (last 200 entries)
