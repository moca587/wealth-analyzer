# Release process

This repo holds **two products** plus an admin console, all in one tree:

| Product | Source (edit these) | Generated (never edit) | Version file |
|---|---|---|---|
| Wealth Analyzer | `wealth-analyzer.html` | `wealth-analyzer-standalone.html` | `version.json` |
| Wealth Analyzer — Avaloq edition | `wealth-analyzer-avaloq.html` | `wealth-analyzer-avaloq-standalone.html` | `version-avaloq.json` |
| Admin console | `admin.html` | `admin-standalone.html` | `version.json` |
| SaaS migration (Stage 1) | `wealth-app-next/` | — (built by Next.js) | — |

Shared source data embedded into the HTML apps:

- `country-accounts.js` — per-country account taxonomy (injected via `inject-accounts.pl`)
- `fund-universe.js` — fund universe (injected via `inject-universe.pl`)
- `vendor/*.min.js` — pinned Chart.js, jsPDF, jsPDF-autotable, pdf.js (+ worker), qrcode

## Source of truth vs generated

**Edit only the source files.** The `*-standalone.html` files and the
`version*.json` files are produced by the build and will be overwritten. A
generated standalone inlines every vendored library and font so it runs fully
offline from a single file.

## Commands

Run from the repository root:

```bash
npm run legacy:build     # regenerate all standalones from source (needs Perl), then validate
npm run legacy:check     # validate the committed artifacts WITHOUT rebuilding
npm run ci               # app tests + type-check + Next build + legacy:check
```

The app-only checks:

```bash
npm run app:install      # npm ci in wealth-app-next
npm run app:test         # vitest run
npm run app:typecheck    # tsc --noEmit
npm run app:build        # next build
```

## The one rule that keeps this repo honest

**If you change a source HTML file (or `country-accounts.js` / `fund-universe.js`),
run `npm run legacy:build` before committing.** That regenerates the standalone,
re-stamps `APP_VERSION`, and writes the version file — all in sync.

### Why this matters (a real bug this prevents)

The live site once fell into an **auto-reload loop**. Root cause: the build
stamped a fresh `APP_VERSION` into the *standalone* and into `version.json`, but
never wrote it back into the *source* `wealth-analyzer.html`. The deployed app's
`APP_VERSION` constant stayed frozen while `version.json` advanced, so the live
update-poller saw a permanent mismatch and reloaded forever.

Both builders now sync the stamp back into their source, and
`check-artifacts.mjs` fails the build if `source APP_VERSION`, the version file,
and the standalone ever disagree. `npm run legacy:check` runs in CI on every PR.

## What `check-artifacts.mjs` verifies

For each app:

1. The version file parses and its `version` is a `YYYYMMDD-HHMM` stamp with `builtAt` + `channel`.
2. **Versions agree**: `source APP_VERSION` === version file === `standalone APP_VERSION`.
3. The standalone is **offline-safe**: no live `<script src="cdnjs…">`, no Google Fonts `<link>`, and the pdf.js `workerSrc` is a blob (not a CDN URL). (Bare CDN *strings* inside minified vendor code are ignored — only live tags fail.)
4. The standalone is a **plausible size** (a tiny file means it lost its inlined libraries).
5. Embedded **data blocks survived** the build (`COUNTRY_ACCOUNTS`, `FUND_UNIVERSE`) for the apps that carry them.

## CI

The workflow (`.github/ci-workflow.yml`) installs `wealth-app-next` deps
(cached), runs the unit tests, type-check, and Next build, then validates the
legacy artifacts. CI **validates** the committed standalones rather than
rebuilding them — so a stale or drifted artifact fails the PR instead of being
silently regenerated.

**Activation:** the file ships at `.github/ci-workflow.yml` because the token
that committed it lacks GitHub's `workflow` scope (pushes touching
`.github/workflows/` are rejected without it). To turn it on, move it into place
from the GitHub web UI or a `workflow`-scoped credential:

```bash
git mv .github/ci-workflow.yml .github/workflows/ci.yml
git commit -m "Activate CI workflow" && git push
```

Once at `.github/workflows/ci.yml` it runs on every push to `main` and every PR.

## Notes / future work

- `build-standalone.py` and `build-docx.pl` / `make-questionnaire.py` are ancillary
  scripts, not part of the standard standalone pipeline.
- Large binaries (sample PDFs, the Avaloq PWA zip, `.docx` outputs) are treated as
  local/artifact material and are gitignored or kept out of the tree — they are not
  regenerated by CI.
- If `country-accounts.js` / `fund-universe.js` grow enough to bloat the SaaS bundle,
  split the TS port (`wealth-app-next/lib/data/`) per-country / dynamic-import.
